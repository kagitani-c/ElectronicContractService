# ElectronicContractService（電子契約SaaS Webアプリケーション）

## 1. プロジェクト概要

業務フローの最適化や導入遅延防止を視野に入れ、要件定義からMVCモデル設計、セキュアな実装までを一貫して検証・構築したSaaS型電子契約サービスのWebアプリケーションです。
単なる機能実装にとどまらず、ビジネスモデル（サブスクリプション導線）と連携した機能要件や、実務に耐えうる堅牢なアーキテクチャを意識して設計しています。

* **開発背景**: 複雑な契約締結プロセスの可視化と、関係者間の認識ズレによる手戻りを防ぐ仕組み化の実践。


* **設計思想**: 不正アクセスや改ざんをシステム論的に排除する厳格なルール設計と、環境非依存で動作するポータビリティの担保。



---

## 2. 機能要件・ビジネスロジック

外部招待ユーザーをシステムに巻き込み、契約締結後に登録ユーザー（サブスクリプション）へと転換させる成長モデルを組み込んだ機能構成です。

* **REQ-01 アカウント・ユーザー管理機能** : 新規アカウント登録（サインアップ）、ログイン認証、および登録ユーザーと招待ユーザーの権限分離管理。


* **REQ-02 アップグレード機能**: 招待ユーザーから登録ユーザーへの移行および顧客情報の引き継ぎ。


* **REQ-03 フォルダ管理機能**: 契約管理フォルダの作成、複数契約書データのグルーピング管理。


* **REQ-04 ドキュメント検索機能**: 契約書タイトル、送信者・受信者のユーザー情報による絞り込み検索。


* **REQ-05 証明書管理機能**: ユーザー情報に対する電子証明書メタデータの紐付け・管理。


* **REQ-06 電子署名付与機能**: 対象ドキュメントに対する署名ステータスおよび署名メタデータの付与。


* **REQ-07 招待・送信機能**: 外部メールアドレス宛ての専用アクセスURL（ワンタイムトークン）発行・通知。


* **REQ-08 ステータス管理機能**: 「作成中」「確認中（送信済）」「締結完了」の厳格なライフサイクル管理。

## 3. 技術スタック

* **バックエンド**: Java（Jakarta EE / Servlet）


* **フロントエンド**: JSP / JSTL / HTML5 / CSS3


* **データベース**: H2 Database（埋め込みモード）


* **データアクセス**: JDBC（PreparedStatement）


* **開発環境・管理ツール**: Eclipse, Git, GitHub, Maven



---

## 4. アーキテクチャと設計のこだわり

* **MVCモデルの徹底と画面隠蔽**:
* View（JSP）を `WEB-INF/jsp/` 配下に配置し、ブラウザからの直接アクセスを物理的に遮断。


* すべてのリクエストが必ずServlet（Controller）を経由する強制ルーティングを敷き、不正な画面改ざんや状態遷移を防止。




* **堅牢なデータベースアクセス（DAO層）**:
* `PreparedStatement` によるプレースホルダー（`?`）処理を徹底し、SQLインジェクション攻撃を防止。


* `try-with-resources` 構文を採用し、ConnectionやResultSetを確実に解放してリソースリークを防止。




* **即時稼働するポータビリティ（再現性）**:
* H2 Databaseの埋め込みモードを採用し、接続URLを相対パス（`jdbc:h2:./data/...`）で管理。


* 外部DBサーバーのインストール不要で、プロジェクトをクローン後すぐに実行・検証できる環境を構築。
